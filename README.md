# Safe Home Agency — აგენტების ტასკ-მენეჯმენტის ბოტი

მარტივი სისტემა Telegram + Google Sheets-ზე: ადმინი (ლაშა) ქმნის დავალებებს,
აგენტები იღებენ შეტყობინებას Telegram-ში, ხედავენ თავიანთ დავალებებს და
ხურავენ, როცა დასრულებულია. ყველაფრის „წყარო" — ერთი Google Sheet.

ეს ინსტრუქცია დაწერილია იმ ვარაუდით, რომ პროგრამისტი არ ხართ — გაყევით
ნაბიჯებს ზუსტად ამ თანმიმდევრობით.

## რა გჭირდებათ

1. Telegram ანგარიში
2. Google ანგარიში (Gmail)
3. უფასო ანგარიში [Railway.app](https://railway.app)-ზე (ბოტის მუდმივად
   გასაშვებად — ის მუშაობს 24/7-ზე, თქვენი კომპიუტერის ჩართვა არ არის საჭირო)

## ნაბიჯი 1 — Telegram ბოტის შექმნა

1. Telegram-ში მოძებნეთ **@BotFather** და დაუწერეთ `/newbot`.
2. მისცეთ სახელი (მაგ. `Safe Home Agency CRM`) და username (უნდა მთავრდებოდეს
   `bot`-ზე, მაგ. `safehome_agency_bot`).
3. BotFather დაგიბრუნებთ **ტოკენს** — ასე გამოიყურება:
   `123456789:AAExampleTokenString...`. ეს ჩაინიშნეთ, დაგჭირდებათ.

## ნაბიჯი 2 — თქვენი (ადმინის) Telegram chat_id-ის მოძებნა

1. მოძებნეთ **@userinfobot** Telegram-ში და დაუწერეთ `/start`.
2. დაგიბრუნებთ თქვენს `Id`-ს (მაგ. `987654321`) — ეს არის `ADMIN_CHAT_IDS`.

## ნაბიჯი 3 — Google Sheet-ის შექმნა

1. გახსენით [sheets.google.com](https://sheets.google.com) და შექმენით ახალი,
   ცარიელი ცხრილი. დაარქვით, მაგალითად, „Safe Home CRM".
2. URL-ში დააკვირდით ასეთ ნაწილს:
   `https://docs.google.com/spreadsheets/d/`**`1AbC...XyZ`**`/edit`
   — გამორჩეული ნაწილი (`1AbC...XyZ`) არის თქვენი `GOOGLE_SHEET_ID`. ჩაინიშნეთ.
3. Tab-ების (Agents, Tasks) და სვეტების შექმნა არ არის საჭირო ხელით —
   ბოტი პირველივე გაშვებისას თავად შექმნის მათ სწორი სათაურებით.

## ნაბიჯი 4 — Google სერვის-აქაუნთის შექმნა (რომ ბოტმა შეძლოს ცხრილთან წვდომა)

1. გახსენით [Google Cloud Console](https://console.cloud.google.com/) და
   შექმენით ახალი პროექტი (ზედა ზოლში „Select a project" → „New Project").
2. მარცხენა მენიუდან: **APIs & Services → Library**. მოძებნეთ და ჩართეთ
   (Enable) ორივე:
   - **Google Sheets API**
   - **Google Drive API**
3. **APIs & Services → Credentials → Create Credentials → Service account**.
   მისცეთ ნებისმიერი სახელი (მაგ. `crm-bot`) და დააჭირეთ „Done".
4. სიაში გახსენით ახლად შექმნილი სერვის-აქაუნთი → ჩანართი **„Keys"** →
   **„Add Key" → „Create new key" → JSON**. ჩამოიტვირთება `.json` ფაილი —
   ეს ინახეთ უსაფრთხოდ (ეს არის „პაროლი", ნურავის გაუზიარებთ).
5. იმავე გვერდზე დააკოპირეთ სერვის-აქაუნთის **email მისამართი**
   (გამოიყურება ასე: `crm-bot@your-project.iam.gserviceaccount.com`).
6. დაბრუნდით თქვენს Google Sheet-ში (ნაბიჯი 3) → **Share** ღილაკი →
   ჩასვით სერვის-აქაუნთის email → მიეცით **Editor** უფლება → Share.
   (ამის გარეშე ბოტი ცხრილს ვერ ნახავს.)

## ნაბიჯი 5 — ბოტის განთავსება Railway-ზე

1. შედით [railway.app](https://railway.app)-ზე და დარეგისტრირდით
   (მოსახერხებელია GitHub ანგარიშით).
2. **New Project → Deploy from GitHub repo** — თუ ეს ფაილები GitHub-ზე ჯერ
   არ გაქვთ ატვირთული, უმარტივესია: **New Project → Empty Project**, შემდეგ
   საწყისი ეკრანიდან აირჩიეთ **„Deploy from local directory"** ან ატვირთეთ
   ეს ფოლდერი GitHub-ის ახალ repo-ში (github.com → New repository →
   ატვირთეთ ეს ფაილები → Railway-ში `Deploy from GitHub repo`).
3. პროექტის **Variables** ტაბში დაამატეთ:

   | სახელი | მნიშვნელობა |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | ნაბიჯი 1-ის ტოკენი |
   | `ADMIN_CHAT_IDS` | ნაბიჯი 2-ის chat_id (თუ რამდენიმე ადმინია, მძიმით: `111,222`) |
   | `GOOGLE_SHEET_ID` | ნაბიჯი 3-ის ID |
   | `GOOGLE_SERVICE_ACCOUNT_JSON` | გახსენით ნაბიჯი 4-ის `.json` ფაილი ტექსტ-რედაქტორში, მთელი შიგთავსი დააკოპირეთ და ჩასვით აქ (ერთ ხაზად) |
   | `TIMEZONE` | `Asia/Tbilisi` |

4. Railway ავტომატურად წაიკითხავს `Procfile`-ს და გაუშვებს `python bot.py`-ს
   `worker`-ის სახით. Deploy-ის დასრულებისას ლოგებში უნდა დაინახოთ
   `ბოტი გაშვებულია...`.

**შენიშვნა:** Railway-ის free tier თვეში გარკვეულ საათებს იძლევა უფასოდ —
მცირე გუნდისთვის საკმარისია. საჭიროების შემთხვევაში მოგვიანებით შეგიძლიათ
გადახვიდეთ ფასიან გეგმაზე ან სხვა მასპინძელზე (Render, Fly.io) — კოდი არ
იცვლება.

## როგორ გამოვიყენოთ

**თქვენთვის (ადმინი/მენეჯერი):**
1. მოძებნეთ ბოტი Telegram-ში, დაუწერეთ `/start`.
2. `/addagent` — დაამატეთ თითო აგენტი (სახელი + ტელეფონის ნომერი, ზუსტად
   ისეთი, როგორითაც თავად იცნობთ მას — ამ ნომრით მოხდება მისი ავტომატური
   ამოცნობა რეგისტრაციისას).
3. სთხოვეთ თითოეულ აგენტს, გახსნას ბოტი და დაწეროს `/start` — გამოეთხოვება
   ნომრის გაზიარება ღილაკით, ერთი შეხებით. **მანამ, სანამ აგენტი არ
   დარეგისტრირდება Telegram-ში, მასზე ავტომატურად ახალი კლიენტი არ
   მიენიჭება** (რადგან შეტყობინებას ვერ მიიღებდა).
4. `/newtask` — ახალი კლიენტის დამატება. ორი გზაა, პირველივე ღილაკებით:
   - **„ზოგადი კლიენტი"** — მხოლოდ ტელეფონი და ქირა/ყიდვა იცით. აგენტს
     **სისტემა თავად ირჩევს**, ბოლო 30 დღის შესრულების მაჩვენებლის
     მიხედვით: **მაღალი** პრიორიტეტის კლიენტი მიდის იმასთან, ვინც
     ყველაზე სწრაფად/საიმედოდ ხურავს დავალებებს (24სთ-ში დახურვის
     პროცენტი), **საშუალო** პრიორიტეტი — ყველაზე სუსტ მაჩვენებელთან
     (ანუ ვინც არ ასწრებს), **დაბალი** — შემთხვევითობით.
   - **„კონკრეტული ბინა (ნახვა)"** — კლიენტი მოვიდა კონკრეტული აგენტის
     უკვე გამოქვეყნებულ ლისტინგზე (მაგ. myhome-ზე). აირჩევთ აგენტს
     ღილაკიდან, შემდეგ ჩაწერთ ლისტინგის ID-ს, კლიენტის ტელეფონს და
     ნახვის დროს — ეს **პირდაპირ იმ აგენტს ერგება** (არ გადის
     შესრულების-მაჩვენებლის ლოგიკაზე).
5. `/agents` — ვინ არის დარეგისტრირებული.
   `/report` — მოკლე სტატუსი ნებისმიერ დროს (ავტომატურადაც მოგივათ
   დილაობით).
   `/ranking` — აგენტების რეიტინგი ბოლო 30 დღეზე (ვინც სწრაფად ხურავს
   დავალებებს vs ვინც აგვიანებს) — იმავე მონაცემებზეა აგებული, რასაც
   `/newtask` იყენებს ავტომატური განაწილებისას.

**რამდენიმე მენეჯერი რომ იყოს:** ყველას თხოვეთ `/start` დაწეროს ბოტს
@userinfobot-ისგან მიღებული საკუთარი `Id`-ის მისაღებად (ნაბიჯი 2-ის
მსგავსად), და ეს ID-ები დაამატეთ Railway-ს `ADMIN_CHAT_IDS`
ცვლადში, მძიმით გამოყოფილი (მაგ. `111111111,222222222,333333333`) —
ყველა მათგანს ექნება იგივე უფლებები (`/newtask`, `/addagent`, `/report`,
`/ranking`).

**აგენტისთვის:**
- `/mytasks` — მისი ღია დავალებები (კლიენტის ტელეფონით და ნახვის დროთი,
  თუ არსებობს).
- დავალების დახურვა: უბრალოდ დააჭირეთ `/done_XXXXXXXX` ლინკს
  (ეგზავნება `/mytasks`-ის პასუხში), ან ხელით `/done XXXXXXXX`.
  **დახურვის დროულობა პირდაპირ მოქმედებს მის მომავალ რეიტინგზე**
  (`/ranking`) — რაც უფრო სწრაფად დახურავს, მით მეტ მაღალი
  პრიორიტეტის კლიენტს მიიღებს შემდეგში.

**პირდაპირ ცხრილში მუშაობაც შესაძლებელია** — თუ Tasks tab-ში ხელით
დაამატებთ ახალ სტრიქონს (`assigned_to`-ში ჩაწერეთ აგენტის `agent_id`,
რომელსაც Agents tab-ში ნახავთ), ბოტი მას წამოიღებს და აგენტს
შეატყობინებს ისევე, თითქოს `/newtask`-ით შეიქმნა (მაგრამ ავტომატური
განაწილების ლოგიკა მხოლოდ `/newtask`-ში მუშაობს — ცხრილში ხელით
ჩაწერისას თავად ირჩევთ `assigned_to`-ს).

## v3 — Slack/Google Forms-ის ჩანაცვლების დაწყება

თქვენი ძველი Slack არხი (`#ონლაინბაზები`) სხვადასხვა Google Forms-ს
იყენებდა. ეს ვერსია ამათგან იმ ფორმებს ცვლის, რომელთა ველებიც უკვე
ვიცი — დანარჩენებზე (ანგარიშფაქტურა, პირბადული ცხრილი, ექსკურსივის
ბაზა) სკრინები რომ გამომიგზავნით, იმავე პრინციპით დავამატებ.

**აგენტისთვის ახალი ბრძანებები:**
- `/clientreport` — ყოფილი „AgentReports" ფორმის ადგილი. აგენტი
  წერს კლიენტის ნომერს, ირჩევს (რამდენიმეს შეიძლება) რა შესრულდა
  (დარეკვა / ნახვა / წინადადება / მოლაპარაკება / გარიგება დაიხურა /
  არ პასუხობს / არ არის დაინტერესებული — სია თავისუფლად შესაცვლელია
  `bot.py`-ში, `REPORT_ACTIONS`), წერს შენიშვნას ან გამოაგზავნის
  ფოტო/დოკუმენტს (ძველი ფორმის „file upload" ველის მაგივრად).
  ინახება ახალ **Reports** tab-ში.
- `/dayoff` — დასვენების დღის მოთხოვნა (თარიღი + მიზეზი). მოთხოვნა
  ავტომატურად მიდის ყველა ადმინთან „✅ დამტკიცება / ❌ უარყოფა"
  ღილაკებით — გადაწყვეტილება მაშინვე ეცნობება აგენტს. ინახება
  **DayOff** tab-ში.

**ადმინისთვის ახალი ბრძანებები:**
- `/findclient <ტელეფონი>` — კლიენტის სრული ისტორია (ყველა
  დავალება + ყველა `/clientreport`) ერთ პასუხში, ყოფილი „კლიენტების
  ბაზა" ფორმის ნაცვლად.
- `/dayoffs` — ყველა დასამტკიცებელი Day off მოთხოვნა თავიდან, თუ
  ღილაკზე ჯერ არ დაგიჭერიათ.
- `/report`-ში ახლა ემატება: დღეს შემოსული `/clientreport`-ების
  რაოდენობა და დასამტკიცებელი Day off მოთხოვნების რაოდენობა — ეს
  ცვლის ძველ „DAILY TL REPORT" ფორმას.

**რაც ჯერ არ არის გადმოტანილი** (მჭირდება ზუსტი ველების სანახავად
სკრინი, თუ არ გამომიგზავნეთ): ანგარიშფაქტურის ფორმა, პირბადული
(კვირის განრიგის) ცხრილი, ექსკურსივის ბაზა.

მაგ. ექსკლუზივზე დამატებით საკონტაქტო/საკადასტრო/სველი წერტილის და
სხვა ველები, რეპორტზე — სრული შენიშვნა და დანართების რაოდენობა).

### 3. „კითხვა მენეჯერს" — სრული დიალოგი Mini App-ში
ახალი ჩანართი „კითხვები" (აგენტსაც და მენეჯერს/თიმლიდერსაც):

  ტელეგრამში.
- მენეჯერი/თიმლიდერი პასუხობს იქვე, Mini App-ის „კითხვები" ტაბიდან —
  პასუხი ერთდროულად ჩანს Mini App-ში (თარიღიანი ისტორია) და

3. ჩასვათ/ატვირთეთ ახალი შიგთავსი → **„Commit changes"**.
4. Railway ავტომატურად ამოიცნობს ახალ commit-ს და თავად დაიწყებს ახალ
   დეპლოის (არ სჭირდება Variables-ის ხელახლა შევსება — ისინი უცვლელი
   რჩება). Deployments ჩანართში დაინახავთ პროგრესს.
5. საჭიროების შემთხვევაში (Google Sheets-ის სვეტების ან ახალი tab-ების
   განახლება — მაგ. v3-ში დამატებული **Reports** და **DayOff**) ბოტი
   ავტომატურად შექმნის/განაახლებს მათ პირველივე გაშვებაზე, ძველ
   მონაცემებს არაფერი მოუვა.
