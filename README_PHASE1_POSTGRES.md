# Phase 1 — გადასვლა Google Sheets-იდან PostgreSQL-ზე

ეს ინსტრუქცია დაწერილია იმ ვარაუდით, რომ პროგრამისტი არ ხართ. გაყევით
ნაბიჯებს ზუსტად ამ თანმიმდევრობით.

**მთავარი დასამშვიდებელი ფაქტი:** სანამ ბოლო ნაბიჯს (7) არ გააკეთებთ,
ბოტი ზუსტად ისე გააგრძელებს მუშაობას, როგორც აქამდე — Google Sheets-ზე.
ახალი ფაილების ატვირთვა თავისთავად არაფერს არ ცვლის.

---

## რა შეიცვალა კოდში (მოკლედ)

- ახალი ფაილები: `schema.sql`, `db.py`, `sheets_postgres.py`,
  `sheets_gspread.py`, `migrate_sheets_to_postgres.py`,
  `ARCHITECTURE_AUDIT.md`, ეს ფაილი.
- `sheets.py` გახდა "გადამრთველი" — ორიგინალი კოდი უცვლელად გადავიდა
  `sheets_gspread.py`-ში.
- `config.py`-ს დაემატა ორი ახალი (არასავალდებულო) ცვლადი:
  `DATA_BACKEND` და `DATABASE_URL`.
- `requirements.txt`-ს დაემატა ერთი ხაზი (`psycopg2-binary`).
- `bot.py`-ს დაემატა ერთი ახალი, ადმინ-მხოლოდ ბრძანება: `/migratepg`.
  არსებული ბრძანებებიდან არცერთი არ შეცვლილა.

## ნაბიჯი 1 — Postgres-ის დამატება Railway-ზე

1. შედით თქვენს Railway-ს პროექტში (იქვე, სადაც ბოტის სერვისია).
2. **+ New** → **Database** → **Add PostgreSQL**.
3. Railway ავტომატურად შექმნის `DATABASE_URL` environment variable-ს და
   ავტომატურად დაუკავშირებს თქვენს ბოტის სერვისს — დამატებით არაფრის
   ხელით ჩაწერა არ გჭირდებათ.

## ნაბიჯი 2 — ახალი ფაილების ატვირთვა GitHub-ზე

ატვირთეთ ყველა ეს ფაილი repo-ს root საქაღალდეში (**Add file → Upload
files**), ისე რომ არსებულს გადააწეროს:

`bot.py`, `config.py`, `requirements.txt`, `sheets.py` (ახლიდან!),
`sheets_gspread.py` (ახალი), `sheets_postgres.py` (ახალი), `db.py`
(ახალი), `schema.sql` (ახალი), `migrate_sheets_to_postgres.py` (ახალი).

Railway ავტომატურად დაიწყებს ხელახლა აწყობას (redeploy). **ამ ეტაპზე
ჯერ არაფერი იცვლება** — `DATA_BACKEND` ჯერ არ დაგისვამთ, ბოტი კვლავ
Google Sheets-ზე მუშაობს.

## ნაბიჯი 3 — Deploy Logs-ის შემოწმება

Railway-ს **Deploy Logs**-ში დარწმუნდით, რომ ბოტი ჩვეულებრივად ჩაირთო
(იგივე ლოგები, რასაც აქამდე ხედავდით — შეცდომების გარეშე).

## ნაბიჯი 4 — სცადეთ ბოტი ჩვეულებრივად

გაუშვით რამდენიმე ცნობილი ბრძანება (`/report`, `/agents`) — ყველაფერი
ისე უნდა იმუშაოს, როგორც აქამდე. თუ რამე გაფუჭდა ამ ეტაპზე, პრობლემა
ახალ ფაილებთან არაა კავშირში (ისინი ჯერ საერთოდ არ გააქტიურებულა) —
შემატყობინეთ და ერთად გავარკვევთ.

## ნაბიჯი 5 — Dry-run მიგრაცია (არაფერს არ წერს, მხოლოდ ითვლის)

Telegram-ში, ადმინის ანგარიშიდან, დაწერეთ ბოტს:

```
/migratepg
```

დაგიბრუნებთ რეპორტს — რამდენი სტრიქონი აქვს დღეს თითო ცხრილს (Agents,
Tasks, Reports და ა.შ.) და რამდენს გადაიტანდა. **ეს ეტაპი არაფერს არ
წერს Postgres-ში** — მხოლოდ დათვლაა.

## ნაბიჯი 6 — ნამდვილი მიგრაცია

თუ ნაბიჯი 5-ის რიცხვები გონივრულად გამოიყურება, დაწერეთ:

```
/migratepg confirm
```

ბოტი გადაიტანს ყველა მონაცემს Postgres-ში და ბოლოს დაგიბრუნებთ
შედარებას: Sheets-ში რამდენი სტრიქონია და Postgres-ში რამდენი გადავიდა
თითო ცხრილში. ყველგან ✅ უნდა ეწეროს.

**ეს ბრძანება უსაფრთხოა ხელახლა გასაშვებადაც** — თუ კიდევ გინდათ
გაუშვათ (მაგ. მას შემდეგ, რაც Sheets-ში კიდევ დაემატა მონაცემი), ისევ
დაწერეთ `/migratepg confirm` — ძველს არ დააორმაგებს, უბრალოდ განაახლებს.

**Google Sheets არაფერს არ ეშლება** — ეს ბრძანება მხოლოდ კითხულობს
Sheets-იდან, არასდროს წერს იქ.

## ნაბიჯი 7 — გადართვა Postgres-ზე (ეს არის ერთადერთი ნაბიჯი, რომელიც
რეალურად ცვლის ბოტის ქცევას)

Railway-ს ბოტის სერვისში, **Variables**-ში დაამატეთ:

```
DATA_BACKEND=postgres
```

შეინახეთ — Railway ავტომატურად გადატვირთავს ბოტს. ამის შემდეგ ბოტი და
Mini App **აღარ ეხება Google Sheets-ს საერთოდ** — ყველაფერი Postgres-ზე
მუშაობს. სცადეთ ისევ ყველა ცნობილი ბრძანება.

## თუ რამე არასწორად წავიდა — უკან დაბრუნება

Railway-ს **Variables**-ში წაშალეთ (ან შეცვალეთ) `DATA_BACKEND` (ან
დააყენეთ `DATA_BACKEND=sheets`) და შეინახეთ. ბოტი მაშინვე ბრუნდება
Google Sheets-ზე მუშაობაზე — Sheets-ის მონაცემები არასდროს შეცვლილა,
ასე რომ არაფერი დაკარგულა.

---

## რა შემდეგ (Phase 1-ის დანარჩენი, ჯერ არ არის გაკეთებული)

- ავტომატური ტესტები (`pytest`) კრიტიკული სცენარებისთვის.
- Postgres-ის რეზერვირების/backup-ის ჩართვა Railway-ზე (Railway-ს
  Postgres add-on-ს აქვს ჩაშენებული ყოველდღიური backup — Settings-ში
  გადამოწმდება).
- სრული RBAC/permission-შემოწმება (დღეს `roles`/`permissions`
  ცხრილები მხოლოდ საფუძველია, ჯერ არაფერს არ განსაზღვრავს ბოტში).
- `audit_log`-ის დაფარვის გაფართოება (დღეს იწერება მხოლოდ: აგენტის
  (დე)აქტივაცია/როლი, dayoff და shift-swap გადაწყვეტილებები).
